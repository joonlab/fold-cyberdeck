# deckd — 폴드8 사이버덱의 맥 서버

폰(FoldLab 사이버덱)이 맥 화면을 보고 조작하게 해 주는 데몬.
**화면**은 ScreenCaptureKit → VideoToolbox H.264 → UDP 로 보내고,
**입력**은 UDP 로 받아 CGEvent 로 주입한다. 의존 라이브러리 없음(순수 Swift + 시스템 프레임워크).

```
[폰 FoldLab]  ──UDP/Tailscale──  [맥 deckd]
   MediaCodec  ←── H.264 Annex-B ──  VideoToolbox ← ScreenCaptureKit
   키보드·트랙볼 ──── 입력 이벤트 ───→  CGEvent
```

## 쓰기

```bash
./run.sh build     # 릴리스 빌드
./run.sh install   # ★ launchd 에 등록 — 재부팅·로그아웃에도 살아 있다
./run.sh           # (수동) Tailscale 주소에만 바인딩해 기동
./run.sh status    # launchd 등록 여부 + 포트
./run.sh logs      # 상주 로그 (~/Library/Logs/deckd.log)
./run.sh restart   # 권한 준 뒤 등
./run.sh stop      # launchd 에서 내리고 정지
./run.sh token     # 폰에 넣을 토큰 출력
```

### 🚨 상주시키면 권한 주체가 바뀐다

수동 실행에서는 TCC(화면 기록·손쉬운 사용) 주체가 **deckd 를 띄운 터미널 앱**이다.
launchd 로 상주시키면 주체가 **deckd 바이너리 자신**이 된다 — 더 좁아서 좋지만, **다시 허용해야 한다.**

```
시스템 설정 → 개인정보 보호 및 보안 → 화면 기록 및 시스템 오디오 녹음 → + → ~/.local/bin/deckd
같은 화면 → 손쉬운 사용 → + → ~/.local/bin/deckd
(파일 선택창에서 ⌘⇧G 로 경로를 붙여넣는다. 허용 뒤 ./run.sh restart)
```

- **상주본은 `~/.local/bin/deckd` 로 복사해 둔다.** TCC 허용은 바이너리 해시에 묶여서,
  개발 중 `swift build` 를 할 때마다 돌고 있는 서비스의 권한이 날아가면 못 쓴다.
  고친 것을 상주본에 반영하려면 `./run.sh build && ./run.sh install`.
  **자체 서명 신원이 심겨 있으면 재승인은 필요 없다**(아래 「자체 서명」). 없으면 ad-hoc 이라 그때마다 재승인.
- **부팅 직후엔 Tailscale 이 아직 안 올라와 있다.** `serve` 가 주소를 최대 120초 기다린다
  (무한 대기 금지 — 못 올라오면 실패로 끝내고 launchd 가 10초 뒤 다시 부른다).
- LaunchAgent 는 **로그인 시** 뜬다. 재부팅 후 로그인하지 않으면 안 뜬다.

토큰은 첫 실행 때 `~/.config/deckd/token` 에 생성된다(0600).

## 권한 두 가지 — 없으면 «조용히» 실패한다

| 권한 | 없으면 | 주체 |
|---|---|---|
| 화면 기록 | `--list-displays` 가 실패 | **실행한 터미널 앱** (cmux/Ghostty/Terminal 각각 별도) |
| 손쉬운 사용 | 키·마우스가 **예외 없이 무시** | 같음 |

기동 시 손쉬운 사용이 없으면 경고를 찍고 권한 요청 창을 띄운다.

### 🚨 「권한 없음」은 **로그가 아니라 TCC DB** 로 갈린다

기동 로그의 경고는 **그 프로세스가 시작한 순간**의 상태다. 그 뒤에 승인해도 로그는 안 바뀐다.
실제로 2026-09-23 에 «손쉬운 사용이 없다»는 경고를 보고 다시 부탁했는데,
DB 를 보니 **경고보다 12초 뒤에 이미 허용돼 있었다.** 필요했던 건 승인이 아니라 `restart` 였다.

```bash
sqlite3 "/Library/Application Support/com.apple.TCC/TCC.db" \
  "select service, client, auth_value, datetime(last_modified,'unixepoch','localtime')
   from access where client like '%deckd%';"
```

**`./run.sh tcc` 가 이걸 한 번에 본다** — auth 값과 함께, TCC 가 기록한 요구조건(`csreq`)을
**지금 바이너리가 만족하는지 `codesign -v -R` 로 직접 묻는다.** (전엔 csreq 꼬리 40 hex 를 cdhash 와 비교했다 —
길이 접두 바이트에 한 번 속았고, 인증서 기반 요구조건은 아예 못 읽는다.)

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 행이 없음 | 아직 **안 물어봄** | 시스템 설정에서 `⊕` 로 추가 |
| `auth=0` | **거부됨** | 목록의 **토글을 켠다**(`⊕` 아님) |
| `auth=2` + **요구조건 불충족** | 옛 빌드·옛 서명의 승인 — **지금 바이너리는 거부된다** | **`⊖` 로 지우고 `⊕` 로 다시 추가** |
| `auth=2` + 요구조건 충족 | 허용 | `./run.sh restart` 로 반영 |

★ **거부 행이 한 번 생기면 macOS 는 다시 묻지 않는다.** 상주 deckd 에 폰이 붙어 캡처를 시도하면
`-3801 The user declined TCCs` 와 함께 **거부 행이 생긴다** — 목록에 deckd 가 보이는데
스위치만 꺼져 있는 상태가 되고 「추가했는데 왜 안 되지」로 헤맨다. **추가가 아니라 켜기다.**

### 🚨 그리고 `auth_value=2` 만으로도 부족하다 — 승인은 **cdhash 에 묶인다**

`swift build && run.sh install` 로 바이너리가 바뀌면, TCC 행은 `auth=2` 로 **남은 채 효력만 사라진다.**
시스템 설정에는 **스위치가 켜진 것처럼 보인다.**

```
TCC 행이 승인한 cdhash : 436c63f8190b7c713cef9f84ace9a3f0a6e0b075
현재 바이너리의 CDHash : edcead0e35210e692d60cb25dd5b51a79e048ec5   ← 거부된다
```

**껐다 켜기로는 안 낫는다.** 토글은 `auth_value`·`last_modified` 만 갱신하고
`csreq`(승인된 코드 신원)는 **보존한다**(2026-09-23 실측: modified 는 갱신됐는데 cdhash 는 그대로).
→ 목록에서 **`⊖` 로 지우고 `⊕` 로 다시 추가**해야 새 해시로 기록된다.

ad-hoc 서명이면 **배포할 때마다 이 작업이 필요하다** — 그래서 자체 서명으로 바꿨다(아래).

### ✅ 자체 서명 — 재배포해도 권한이 유지된다 (2026-09-24)

`run.sh build` 가 빌드 뒤 **자체 서명 인증서**로 서명한다. TCC 가 기록하는 요구조건이
`identifier deckd and certificate leaf = H"<인증서 해시>"` 가 되어 **내용이 바뀌어도 같은 인증서로 서명한 한 유지된다.**

```bash
./run.sh sign-setup   # 맥마다 한 번. 인증서가 없으면 만들고, deckd 전용 키체인에 심는다
```

- **두 맥이 같은 인증서를 쓴다.** 두 번째 맥에는 첫 맥의 `~/.config/deckd/signing/`
  (`cert.pem`·`key.pem`·`deckd-sign.p12`·`p12.pw`)를 복사해 온 뒤 `sign-setup` 을 돌린다.
- 키는 **deckd 전용 키체인**(`~/Library/Keychains/deckd-signing.keychain-db`)에 있고, 암호는 `signing/keychain.pw`(0600).
  ssh 에서도 서명된다(`set-key-partition-list` 로 GUI 허용 창을 없앴다).
- ⚠️ **이 키로 서명한 것은 무엇이든 deckd 의 두 권한을 물려받는다.** 키를 다른 곳에 두지 말 것.
- 신원이 없으면 경고를 찍고 ad-hoc 으로 남는다(빌드는 성공).

**실측 (노트북·홈맥)** — 인증서 기반으로 ⊖⊕ 한 번 → 소스를 일부러 바꿔 cdhash 가 바뀐 빌드를 install
→ **⊖⊕ 없이** `run.sh tcc` ✅ ✅ · 손쉬운 사용 경고 없음 · HELLO 프로브 캡처 정상 → 되돌린 빌드로 한 번 더 같은 결과.

🚨 함정 둘
- **`codesign --keychain <파일>` 만으로는 신원을 못 찾는다**(`no identity found`). 키체인이 **검색 목록**에
  있어야 한다 — `sign_bin` 이 서명하는 동안만 넣고 원래 목록으로 되돌린다(원래 목록을 못 읽으면 건드리지 않는다).
- 인증서 **신뢰 설정은 필요 없다.** `find-identity` 가 `CSSMERR_TP_NOT_TRUSTED`·「0 valid identities」라고 해도
  해시로 지정하면 서명되고, TCC 도 그 요구조건으로 승인한다. (신뢰를 켜려면 GUI 암호 창이 뜬다 — 안 해도 된다.)

⚠️ `tccutil reset <서비스>` 로 지우려 하지 말 것 — 인자가 `BUNDLE_ID` 인데 우리 항목은 경로다.
인자가 무시되면 그 맥의 **모든 앱**이 그 권한을 잃는다(홈맥 기준 화면 기록 47개).

## 🚨 같은 랜이 아니면 — 키프레임이 통째로 깨진다

2026-09-23 실측. 노트북(같은 랜)은 완벽한데 홈맥만 「미션컨트롤 뒤 앱을 고르면 화면이 깨진다」였다.

| | 노트북 (같은 랜, RTT 6~9ms) | 홈맥 (국제 구간, RTT 58ms) |
|---|---|---|
| 키프레임 완전 수신 | 10/10 (100%) | **0/8 (0%)** |
| 키프레임 조각 유실 | 0.0% | **27.0%** |
| 델타 프레임 | 0% 유실 | **0% 유실** |

**델타는 멀쩡한데 키프레임만 깨진다.** 장면 전환(미션컨트롤→앱)은 큰 I-프레임을 만들고,
그게 통째로 유실되면 다음 키프레임(최대 4초)까지 깨진 화면이 남는다.

원인 둘이 겹쳐 있었다:

1. **페이싱 상한이 목표 비트레이트와 무관했다.** 「12조각마다 200µs」 = 약 576Mbps 로,
   바로 위 주석의 「약 40Mbps」와 **14배 어긋나** 있었다. 같은 랜에서는 안 드러난다.
   → 이제 `bitrate × 3` 에서 유도하고 `--burst-mbps` 로 조절한다.
2. **국제 구간 자체가 흔들린다.** deckd 를 빼고 순수 UDP 로 재도
   5Mbps 2.8% / 10Mbps 11.5% / **20Mbps 0.0%** / 40Mbps 26.5% 로 **단조가 아니다**.
   → 상수를 더 만지는 것은 노이즈 쫓기다. 순위를 매기려 하지 말 것.

### ✅ 해결 — 조각 단위 재전송(NACK)

클라는 **어느 조각이 없는지 정확히 안다.** 그 번호만 요청하면 왕복 한 번으로 끝난다.
`FRAG_NACK`(0x51) 로 그렇게 했다. 같은 국제 구간에서 실측(20초 × 2):

| | NACK 끔 | NACK 켬 |
|---|---|---|
| 키프레임 완주 | 64.3% · 92.3% | **100% · 100%** |
| 끝까지 못 받은 조각 | 5.5% · 1.9% | **0.0% · 0.0%** |
| 덧붙는 트래픽 | — | 요청한 조각 **전체의 4~10%** |

**원래 화질(2048 폭 · 10Mbps)에서도 100% · 0%** 다. 그전에 쓰던
`--max-width 1280 --bitrate 4000000` 우회는 **더 이상 필요 없다.**

머신별 인자가 필요하면 **`~/.config/deckd/args`** 에 둔다
(plist 는 `install` 이 다시 쓰므로 거기 적으면 날아간다):

```
--burst-mbps 12        # 예: 업링크가 더 좁은 망이라면
```

### 왜 «키프레임 전체 재요청»이 나빴나

조각 하나가 없어서 **169조각을 다시** 받는 셈이었고, 그것도 또 깨졌다.
버스트를 더 조이면 오히려 키프레임 생성이 늘어 **악화되는 되먹임**이 관측됐다
(5Mbps 가 10Mbps 보다 나빴다 — 키프레임 8 → 11개). 클라 쪽에 1초 게이트를 걸어 끊었다.

⚠️ `Protocol.swift` ↔ `Protocol.kt` 는 **바이트 단위로 같아야 한다.** 한쪽만 고치면 조용히 어긋난다.

## 옵션

```
--bind <ip>        바인딩 주소 (run.sh 가 Tailscale 주소를 자동으로 넣는다)
--port <n>         UDP 포트 (기본 8790)
--fps <n>          목표 프레임레이트 (기본 30)
--bitrate <bps>    목표 비트레이트 (기본 10000000)
--display <id>     처음 캡처할 디스플레이 (기본: 주 화면). 폰에서 바꿀 수 있다
--max-width <px>   스트림 가로 상한 (기본 2048)
--autoresize       대상 디스플레이를 «폰 비율 + 작은 포인트» HiDPI 모드로 바꾼다 (가상 화면 전용)
--deck-points <n>  --autoresize 가 노릴 포인트 가로폭 (기본 840). 작을수록 폰에서 글자가 크다
--no-cursor        맥 커서를 화면에 그리지 않는다
--list-displays    디스플레이 목록
--print-protocol-golden  DISPLAYS 골든 바이트열 (run.sh golden 이 폰 쪽과 대조)
--dry-input        입력을 주입하지 않고 푼 결과(클릭 모디파이어 포함)·절대좌표 환산만 로그로 (검증용)
--decode-input <hex>  INPUT 배치 본문을 풀어 한 줄로 (run.sh golden 이 폰 인코더와 대조)
-v                 프레임·입력 로그
```

## 실측으로 알아낸 함정 (macOS 26.6.2 · 2026-09-22)

### 🚨 마우스 절대좌표는 `CGWarpMouseCursorPosition` 으로만 정확하다

| 방법 | 커서가 목표에 가나 |
|---|---|
| `CGWarpMouseCursorPosition` | ✅ 정확 |
| `mouseDown` / `mouseUp` 이벤트 | ✅ 안 밀린다 |
| `mouseMoved` / `mouseDragged` 이벤트 | ❌ **밀린다** |

posting 한 이동 이벤트는 «현재 위치 → 이벤트 좌표» 델타에 시스템 포인터 가속을 먹인다.
(400,300) 을 보내면 (554.9, 440.6) 에 떨어진다.
`source=nil` · `privateState` · 델타 0 고정 · warp 선행 — **네 가지 모두 소수점까지 같은 결과**였다.
그래서 위치는 warp 로 잡고, 이벤트는 «앱에게 좌표를 알리기 위해서만» 보낸다(드래그일 때만).

### 더블클릭은 서버가 만든다 — 폰은 «클릭 두 번»만 보내면 된다

macOS 의 더블클릭은 별도 이벤트가 아니라 **`kCGMouseEventClickState` 가 2 인 클릭**이다.
그래서 `InputInjector` 가 0.35초 안의 연속 클릭을 세어 clickState 를 2·3 으로 올린다
(실제 마우스와 같은 방식). 폰은 탭할 때마다 평범한 down/up 을 보내기만 하면 된다.

⚠️ 거꾸로, **폰이 두 번째 탭을 삼키면 이 기능이 죽는다.** 실제로 FoldLab 이
`detectTapGestures(onDoubleTap = …)` 로 두 번째 탭을 «더블탭»으로 가로채고 있어서
맥에 더블클릭이 한 번도 도착하지 못했다(2026-09-22 계측 테스트로 발견).

### 🚨 세션 없이 STATS 를 보내면 재시작 때 영구 교착

클라는 «최근에 뭔가 받았으면 연결됨» 으로 판정하기 쉬운데, 그러면 서버가 재시작해
세션이 없는 상태에서 PONG·STATS 만 답해도 클라가 «연결됨» 으로 오판해 HELLO 를 다시 안 보낸다.
→ **STATS 는 스트리밍 중일 때만** 보내고, **sessionId 를 함께 실어** 클라가 바뀐 것을 알아채게 한다.

## 보조 모니터 — 폰에서 화면을 고른다 (2026-09-23 21차)

폰의 서버 태그(`● 노트북`) 옆에 **디스플레이 태그**가 뜬다(화면이 둘 이상일 때만). 탭하면 다음 화면으로 넘어간다.

| 패킷 | 방향 | 본문 |
|---|---|---|
| `DISPLAYS` 0x62 | 서버→클라 | `u8 count` + `{u32 id · u16 w · u16 h(pt) · u8 flags · u8 len · 이름 UTF-8}` × count. flags = 내장·주 화면·현재 |
| `SELECT_DISPLAY` 0x63 | 클라→서버 | `u32 id` |

- `DISPLAYS` 는 WELCOME 뒤·5초마다(UDP 유실 대비)·모니터를 꽂고 뽑을 때(1초 폴링) 간다.
- 전환하면 캡처를 새로 걸고 **크롭(줌)을 전체로**, 새 WELCOME(스트림 크기)과 키프레임을 준다. 폰도 줌을 되돌린다.
- 보던 화면을 뽑으면 기본 화면으로 돌아간다.

### 🚨 안전 규칙 — 9/22 사고의 세 겹을 풀지 않는다

1. 폰의 선택은 **캡처 대상만** 바꾼다. 해상도·배치·주 화면은 건드리지 않는다.
2. 모드 변경(`fitDisplay`)은 `shouldFit()` 한 곳에서만 정한다 — **`--autoresize` + CLI `--display` 로 명시한 바로 그 id** 일 때만.
   전에는 `reconfigure` 가 `capture.displayID` 를 그대로 넘겼다 — 폰이 외장을 고르는 순간 그 해상도를 바꿀 경로였다.
3. 서버는 **방금 조회한 목록에 있는 id 만** 받는다. 없는 id 는 로그만 남기고 목록을 다시 보낸다.
4. 대상 선택은 여전히 `pickDisplay()` 하나다 — 우선순위 **폰의 선택 → CLI `--display` → 주 화면**.

### 실측 (노트북 + FlipAction16, 외장이 왼쪽 위 · 원점 `(-243,-1200)`)

| | 결과 |
|---|---|
| 외장 선택 | 새 WELCOME `1818x1136` · 현재=5 · 영상 정상 |
| 없는 id | 거절 · 목록 재전송 · 현재 유지 |
| 모드 | 전환 전후 **동일** (`dispmode` 로 대조) |
| 좌표(`--dry-input`) | (0,0)→(−243,−1200) · 중앙→(717,−600) · 2배 줌 (0,0)→(237,−900) — **전부 기대값** |

🚨 곁가지로 잡은 것 둘
- **절대좌표가 화면 밖 한 픽셀로 샜다.** 스트림 끝 (W,H) 가 maxX·maxY 로 환산돼, 위에 둔 외장에서 (1677, 0) =
  **내장 화면 맨 윗줄**이 됐다. `mapAbsolute` 가 보는 영역 안쪽으로 가둔다 → (1676, −1).
- **`capture.start` 가 돌던 스트림을 안 멈췄다.** 전환·뷰포트 재접속마다 캡처가 둘이 됐을 것이다. 이제 먼저 `stop()`.

## 모디파이어 + 클릭 (2026-09-24)

폰에서 ⌘·opt·^·⇧ 를 켜고 클릭하면 **그 클릭에** 모디파이어가 실린다. INPUT 종류 `9 mouseDownMods` · `10 mouseUpMods`(u8 button · u32 flags)는
**모디파이어가 있을 때만** 쓰고, 평범한 클릭은 옛 5/6 그대로다. 서버는 ⇧^⌥⌘ 외 비트를 버리고, 드래그·떼기는 누를 때의 flags 를 쓴다.
모든 마우스 이벤트는 flags 를 **명시**한다 — 비우면 소스에 고착된 Control 을 물려받아 좌클릭이 우클릭이 된다(9/22 사고).

## 기본은 «맥 본 화면 그대로»다

Dock·메뉴바·창 신호등까지 실제 화면을 그대로 잡는다. 가상 화면을 쓰고 싶을 때만 `--display` 로 지정한다.

### 폰에서 글자가 작으면 — **핀치로 확대한다 (서버가 잘라 보낸다)**

폰에서 두 손가락으로 벌리면 그 영역만 서버가 잘라 **원본 픽셀로** 꽉 채워 보낸다.
클라이언트에서 확대하는 것과 달리 **뭉개지지 않는다.** 손을 떼고 축소하면 다시 전체가 보인다.

- 핀치 = 확대/축소(1~6배) · 한 손가락 드래그 = 이동 · 더블탭 = 원래대로
- 텔레메트리의 `⤢` 칩을 누르면 1 → 1.5 → 2 → 3배 로 순환(한 손으로 된다)
- 확대 중에도 **탭 좌표와 트랙볼 속도가 배율에 맞게 환산된다**
  (실측: 2배 확대 상태에서 스트림 정중앙 탭 → 화면 (756,485), 기대 (756,490))

프로토콜은 `VIEW`(0x61) 하나 — 보는 영역을 디스플레이 대비 **정규화 0~65535** 로 보낸다.
포인트로 주고받으면 폰이 맥의 포인트 크기를 알아야 해서 왕복이 한 번 더 생긴다.

## 가상 화면을 쓰고 싶다면 — 포인트 수를 줄인다

맥 본 화면(1512pt)을 폰 상단 절반에 통째로 넣으면 글자가 물리적으로 절반이 돼 못 읽는다.
**해상도를 올려서는 못 고친다** — 오히려 더 작아진다. 참고한 원격 앱 영상이 가상 디스플레이를
704x536·896x682 **포인트**로 쓴 이유가 이것이다.

```bash
open -a DeskPad                       # 가상 디스플레이 생성 (창을 닫으면 사라진다)
./run.sh -- --autoresize              # deckd 가 폰 비율에 맞는 HiDPI 모드를 골라 적용
```

### 🚨 `--autoresize` 는 반드시 `--display <id>` 와 함께 쓴다

**«비내장 화면»을 알아서 고르게 두면 안 된다.** DeskPad 같은 가상 화면과 사용자의 **진짜 외장 모니터**는
`CGDisplayIsBuiltin` 으로 구별되지 않는다.

> 실제 사고(2026-09-22): `--autoresize` 가 연결돼 있던 16" 휴대용 모니터 `FlipAction16` 을
> **840x525pt 로 바꿔 버렸고**, 게다가 캡처 대상까지 그 모니터가 되어 폰이 그걸 미러링했다.
> 원인 둘 — ①`--autoresize` 가 비내장 중 첫 번째를 골랐다 ②대상 선택 로직이 `main.swift` 와
> `Capture.swift` **두 곳에 흩어져 있어** 한쪽만 «본 화면 우선»으로 고쳤다.
> 지금은 대상 선택이 `pickDisplay()` 한 곳이고, `--autoresize` 는 `--display` 없이는 아무것도 안 한다.

```bash
./run.sh -- --list-displays                  # id 확인
./run.sh -- --display <가상화면id> --autoresize
```

**안전장치 세 겹** (사고 후 추가)
1. `--autoresize` 는 `--display <id>` 없이는 **아무것도 하지 않는다**
2. 모드 변경은 `.permanently` 가 아니라 **`.forSession`** — 실수해도 로그아웃/재부팅이면 저절로 낫는다
   (`.permanently` 면 재부팅해도 남아서, 사용자가 원인을 모른 채 계속 그 해상도로 쓰게 된다)
3. 바꾸기 **전** 모드를 기억해 두고 종료(SIGINT/SIGTERM/atexit)할 때 **되돌린다**
   — 검증: DeskPad 3360x2100pt → 840x525pt → SIGTERM → **3360x2100pt 복귀**

실측(DeskPad, 폰 1848x1171): `840x525pt / 1680x1050px` 가 선택된다.
글자가 1.8배 커지고, **14" 맥북에서 보던 것과 거의 같은 물리 크기**가 된다.

| 포인트 | 픽셀 | 폰에서 글자 | 비고 |
|---|---|---|---|
| 840x525 | 1680x1050 | **1.80배** | 기본. 데스크탑에 쓸 수 있는 16:10 HiDPI 중 최소 |
| 960x600 | 1920x1200 | 1.57배 | 업스케일 0 — 가장 선명 |
| 1280x800 | 2560x1600 | 1.18배 | 정보량 우선 |

⚠️ 가상 화면에는 **창을 직접 옮겨 놔야** 보인다. DeskPad 창 자체를 그 화면 위에 두면 무한거울이 된다.

### 🚨 `isUsableForDesktopGUI` 를 반드시 본다

`CGDisplayCopyAllDisplayModes` 목록에는 800x500·720x450 같은 더 작은 HiDPI 모드가 버젓이 들어 있지만
대부분 **usable=false** 이고, 그걸 지정하면 `CGCompleteDisplayConfiguration` 이
**1001(illegalArgument)** 로 **조용히** 거부한다. 실측: HiDPI 26개 중 쓸 수 있는 16:10 은 840x525 이 최소.

## 🚨 키프레임을 버스트로 쏟으면 «연결은 되는데 화면만 검다»

1680x1050 으로 올리자 재현됐다. 키프레임 한 장이 ~200KB = 170여 패킷이라 한꺼번에 보내면
수신 측에서 그 프레임만 통째로 유실된다. 델타 프레임(작다)은 멀쩡히 도착하므로
**연결 ✅ · 수신 ✅ · 텔레메트리 정상 · 화면만 검은** 형태가 된다 — IDR 이 한 번도 완성되지 않으면
디코더는 영영 시작하지 못한다. 진단은 텔레메트리의 **유실 조각 수**.
→ 12패킷마다 200µs 쉬어 약 57MB/s 로 눌러 보낸다. 지연은 프레임당 ~2ms 늘고 유실은 0 이 됐다.

## 🚨 「탭했는데 우클릭이 된다」 — 모디파이어 플래그가 이벤트 소스에 남는다

posting 한 키 이벤트의 모디파이어 플래그는 **이벤트 소스 상태에 그대로 남는다.**
실제 키보드는 «모디파이어를 떼는» flagsChanged 가 따로 나오는데 우리는 그걸 안 보내기 때문이다.

```
^Fn→ 한 번 보낸 뒤 → CGEventSourceFlagsState = 0x20840000 [Ctrl, Fn]  (고착)
그 상태에서 만든 마우스 이벤트 → 같은 플래그를 물려받음
→ Control + 좌클릭 = macOS 에서 **우클릭**
```

키 이벤트는 우리가 매번 플래그를 명시해서 멀쩡했고, **마우스만 오염됐다.**
그래서 증상이 «타이핑은 되는데 탭이 자꾸 우클릭»으로 나타난다.
스티키 `^`·`⌥`·`⌘` 키를 한 번이라도 쓰면 같은 일이 생긴다.

**두 겹으로 막는다**
1. **마우스·스크롤·유니코드 이벤트에 `e.flags = []` 를 못 박는다** — 소스가 오염돼도 안 물려받는다
   (Shift 가 묻으면 세로 스크롤이 가로로 바뀌는 문제도 같이 막힌다)
2. **모디파이어가 붙은 keyUp 뒤에 소스 상태를 지운다** — Control 키(0x3B)를 `flags=0` 으로
   «떼는» 이벤트 하나면 상태 전체가 지워진다(실측)

검증: `^Fn→`·`◀SP`·스티키 `⌘`+글자 — 전부 보낸 뒤 소스 상태 `깨끗`.
